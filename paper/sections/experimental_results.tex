\section{Experimental Results}

To evaluate the proposed methodology, we implemented the graph conversion algorithm within the FlatZinc modeling ecosystem. We selected 300 instances from the 2023, 2024, and 2025 MiniZinc Challenges to construct three algorithm selection tasks: (i) maximizing the Borda count score across three solvers, (ii) maximizing prediction accuracy for the same solver set, and (iii) predicting whether a parallel solver execution provides a significant performance gain over its sequential counterpart.\todo{some justification and motivation behind this choice} Solvers, in all tasks, were executed with the \texttt{--free-search} flag enabled\footnote{\url{https://docs.minizinc.dev/en/stable/command\_line.html\#cmdoption-f}} on an Intel Xeon Gold 6130 processor with a 20-minute timeout.

Our approach is compared against two baselines: a standard performance baseline and \texttt{fzn2feat} \cite{Amadini2014-fn}, a feature set specifically engineered for constraint programming algorithm selection. \todo{in background some info on this?}

Given the limited depth of our graph representations (see Section~\ref{sec:feature_characteristics}), we evaluate \texttt{WL} features using one and two aggregation steps. 

For each task, we trained three models: Support Vector Machines (SVM), Random Forests (RF), and three-layer Multi-Layer Perceptrons (MLP).\todo{why?} The training pipeline followed a four-step protocol:
\begin{enumerate}
    \item \textbf{Hyperparameter Optimization:} We performed a grid search over predefined configurations, evaluating each via mean 5-fold cross-validation.\todo{repeated nested cross validation with inner for hyperparameter tuning?}
    \item \textbf{Model Selection:} We selected the highest-scoring configuration. Ties were broken by prioritizing simpler models to mitigate overfitting:
    \begin{itemize}
        \item For SVM: lower regularization ($C$) and $\gamma$ values, favoring the RBF kernel.
        \item For RF: fewer trees and shallower maximum depth.
        \item For MLP: fewer training steps and a smaller $\alpha$ penalty.
    \end{itemize}
    \item \textbf{Dimensionality Reduction:} We evaluated the best configuration on reduced feature sets using Principal Component Analysis (PCA) in the range $[20, \min(\text{n\_features}, \text{n\_samples})[$ with a step size of 20.
    \item \textbf{Final Feature Selection:} The feature set (original or PCA-transformed) yielding the highest cross-validation score was selected for final evaluation.
\end{enumerate}

The last two steps (Dimensionality Reduction and Final Feature Selection) have been skipped for MLP classifiers due to their ability to handle high-dimensional data.

The selection of SVM, RF, and MLP provides an evaluation framework that tests feature sets against three distinct mathematical paradigms: geometric margin optimization, ensemble-based logical partitioning, and connectionist functional approximation. Together, these models ensure that the observed performance of the new features is robust across different algorithmic structures and not an artifact of a single learning bias.
Our training protocol prioritizes model generalization by combining exhaustive grid search with a complexity-penalizing selection logic. While the SVM and RF models were subjected to an iterative PCA-based dimensionality reduction to minimize noise and multicollinearity, this step was bypassed for the MLP. This distinction acknowledges the MLP's native capacity for high-dimensional representation learning and internal feature weighting, thereby avoiding the potential loss of information associated with extrinsic linear transformations like PCA.

All figures group together features extracted with the same methodology but with different aggregation steps using an alternated shaded background to improve readability.

\subsection{Borda Count Score Maximization}\label{sec:borda-cout}
In this task, we compare three sequential solvers: \texttt{OR-Tools} \cite{or-tools}, \texttt{Chuffed} \cite{chuffed}, and \texttt{CPLEX} \cite{Nickel2022-eb} on the 300 instances. Scores were assigned based on the Borda count strategy used in the MiniZinc Challenge.\footnote{\url{https://www.minizinc.org/challenge/2025/}} We framed this as a classification problem where the target label is the solver achieving the highest score. 

We excluded one trivially unsatisfiable instance from which features could not be extracted, as well as instances where no solver reached a solution. The final dataset comprised 289 instances. Evaluation consisted of 10 repetitions of 5-fold cross-validation (50 total trials). We employed \texttt{StratifiedKFold} from Scikit-learn\footnote{\url{https://scikit-learn.org/stable/modules/generated/sklearn.model\_selection.StratifiedKFold.html}}, stratifying based on the performance gap between the Virtual Best Solver (VBS) and the worst-performing solver in the portfolio.

Figure \ref{fig:svc-wlc-fzn2feat-scores} illustrates the performance of SVM models trained on \texttt{WL}-based features. While all feature sets generally outperformed the baseline, incorporating node information (\texttt{WLn}) yielded a significant performance increase over standard \texttt{WL} features. Conversely, edge information (\texttt{WLe}) provided no substantial predictive signal. Combining node and edge attributes (\texttt{WLne}) did not further improve results beyond the node-only baseline. 

Notably, features derived from the cut-based representation (\texttt{WLc} and \texttt{WLce}) significantly outperformed all other variants. The number of aggregation steps had negligible impact on final performance across all feature sets. Although \texttt{WLc-1} was the only configuration to consistently exceed the baseline ($> 1$), the performance differences between various cut-based features were not statistically significant, likely due to high variance inherent in the task. Finally, also in Figure \ref{fig:svc-wlc-fzn2feat-scores}, all cut-based models statistically outperformed the \texttt{fzn2feat} baseline.

Since RF and MLP classifiers exhibit performance trends similar to those of the SVM on \texttt{WL}-based features, we provide their comprehensive comparisons in the Appendix. We will now focus only on the performance of cut-based features relative to the \texttt{fzn2feat} baseline for these models.

Figure \ref{fig:forest-nn-wlc-fzn2feat-scores} illustrates the comparative performance of RF and MLP models. For the RF, \texttt{fzn2feat} achieves marginally higher scores than the cut-based features with the exception of \texttt{WLce-2} which still presents slightly higher mean and median scores, though these differences are not statistically significant ($p > 0.5$). In the MLP evaluation, only \texttt{WLc-2} significantly outperforms \texttt{fzn2feat} ($p = 0.04$), while the improvement for \texttt{WLc-1} is marginal and falls outside the significance threshold ($p = 0.054$). 

Finally, we conducted a cross-model comparison between the best-performing \texttt{fzn2feat} configuration (RF) and the best cut-based configuration (SVM). No statistically significant difference was observed, with the lowest recorded $p$-value being $0.33$. However, it is noteworthy that all cut-based feature sets yielded higher mean and median scores than \texttt{fzn2feat} across these comparisons but with limited effect size (Cohen's d\cite{Diener2010-rf} $<0.2$) indicates that the high variance inherent in solver performance on the MiniZinc Challenge instances remains a dominant factor.

Finally, it is noteworthy to point out that we deliberately decided to exclude the feature extraction cost from the results since our current implementation of the feature extraction isn't well optimised and its performance are sub-optimal. A more detailed discussion about it can be found in Section \ref{sec:extraction-cost}.

\subsection{Algorithm Selection with Accuracy Maximisation}
The setup for this task was the same as for the borda count maximisation one (in Section \ref{sec:borda-cout}) with the only difference being the objective of the task which changes from maximising the score of the portfolio to maximising predictive accuracy. This change will allow us to use different statistical tests such as the Mcnemar test \cite{Smith2020-cb}. In this task, the baseline to beat is the majority classifier which always predicts the most frequent label.


The experimental configuration for this task mirrors the Borda count maximization setup (Section \ref{sec:borda-cout}), with the objective shifted to maximizing predictive accuracy. This change of objective was also reflected in the stratification strategy which is based on the final label instead of the gap. This shift allows for the application of additional statistical evaluations, specifically the McNemar test \cite{Smith2020-cb}, to assess the significance of differences in classifier performance. In this context, the baseline for comparison is the ZeroR (majority) classifier, which consistently predicts the most frequent class label in the training set.

Statistical significance relative to the majority classifier (MC) baseline is determined via Wilcoxon signed-rank and McNemar tests ($\alpha = 0.05$). Significance between the cut-based features and \texttt{fzn2feat} was evaluated using McNemar and Wilcoxon signed-rank tests ($p < 0.01$).}
    \label{fig:svc-accuracy}
\end{figure}

Consistent with the observations in Section \ref{sec:borda-cout}, the comparisons of \texttt{WL}-based features for SVM models (Figure \ref{fig:svc-accuracy}, right) indicate that cut-based features significantly outperform alternative variants. However, for the accuracy maximization task, the marginal benefit of incorporating node information is less pronounced than in the Borda count task. Regardless, all feature configurations demonstrate a statistically significant improvement over the majority classifier baseline.

When compared against the \texttt{fzn2feat} baseline (Figure \ref{fig:svc-accuracy}, left), cut-based features exhibit significantly higher accuracy. This performance gain is confirmed by both McNemar and Wilcoxon signed-rank tests, with $p$-values below $0.01$. Conversely, inter-model comparisons between the various cut-based feature sets do not yield statistically significant differences.

When comparing the best \texttt{fzn2feat} classifier with the best cut-based ones, both \texttt{WLc-1} and \texttt{WLc-2}-based models are significantly better using the McNemar test while only the \texttt{WLc-1}-based model is better using the Wilcoxon signed-rank tests.

\subsection{Feature Extraction Cost}\label{sec:extraction-cost}
The computational overhead for extracting cut-based features compared to \texttt{fzn2feat} is illustrated in Figure \ref{fig:extraction-time}. Because both methodologies necessitate a preliminary compilation from MiniZinc to FlatZinc, we exclude compilation time from the reported extraction costs to isolate the performance of the feature generators themselves. 

While \texttt{fzn2feat} exhibits lower absolute extraction times, the vast majority of instances require less than one second even when utilizing cut-based features. It is important to note that the current implementation of the \texttt{WL} feature extraction pipeline (comprising graph conversion and Weisfeiler-Lehman aggregation) is not fully optimized. Significant performance gains could be realized through algorithmic refinements and the parallelization of independent graph operations, further reducing the overhead for large-scale instance sets.
